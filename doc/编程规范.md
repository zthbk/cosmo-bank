# WVP-Pro 后端编程规范

> 状态：v2.0 | 日期：2026-11-06 | 适用范围：清理后基线（JDK 17、MySQL 8.4、当前无前端工程）
>
> 关联文档：`README.md`、`AGENTS.md`、`文档/冗余代码与文件清理计划.local.md`、`文档/C3平台级联方法级清单.local.md`。

## 1. 总则

- 新代码必须遵守本规范，存量代码逐步靠拢；不把历史问题当成模板。
- 先读后改：修改前阅读目标文件与调用链，不做无关格式化、重排或顺手重构。
- 修改范围最小化；一个提交只做一件事。
- 已删除模块不得恢复，详见第 3 节。
- 结论先行：分析、评审、排障先给结论，再给证据（文件路径、行号、命令输出）。

## 2. 技术基线

表 1 给出当前技术基线，新增依赖或写法不得偏离。

| 项目 | 基线 | 约束 |
|---|---|---|
| JDK | 17 | 不使用虚拟线程、JDK 21+ 专属 API |
| Spring Boot | 3.4.4 | 单 Maven 模块 |
| 数据库 | MySQL 8.4 | 仅 MySQL，不新增其他驱动、方言或 `databaseId` 分支 |
| 缓存 | Redis | 设备状态、InviteInfo、SIP 事务、集群消息 |
| 媒体 | ZLMediaKit | 仅 ZLM，不新增其他媒体节点实现 |
| SIP | Jain SIP 1.3.0-91 | GB28181 信令 |
| 前端 | 待建 | 当前无 `web/`；目标 Vue 3 + Vite 6 + Element Plus |

- 时间统一 `Asia/Shanghai`；数据库脚本按版本维护，无 Flyway/Liquibase。
- 不引入已删除模块的依赖或配置。

## 3. 分层与包结构

表 2 给出后端包职责。

| 包 | 职责 |
|---|---|
| `gb28181/` | SIP 信令、设备/通道、点播、回放、PTZ、位置 |
| `media/` | ZLMediaKit 接入、媒体 Bean/Event |
| `service/` | 跨模块服务、录像、告警、集群 RPC |
| `storager/` | Redis 缓存与 DAO |
| `vmanager/` | 管理 API（用户、告警、云录像、录像计划、服务控制） |
| `web/gb28181/` | 外部兼容 API（`/api/v1`） |
| `conf/` | 配置、安全、调度、Redis |
| `utils/` | 时间、媒体、通用工具 |

- Controller 只做参数校验、调用 Service、组织响应；业务逻辑、SQL、Redis 操作下沉到 Service/DAO。
- 新增领域代码放对应业务包，不把所有工具类塞进 `utils`。
- **不得恢复**：`jt1078/`、`conf/ftpServer/`、`media/abl/`、`streamProxy/`、`streamPush/`、`web/custom/`（`/api/sy`）、地图/矢量瓦片。
- **C3 平台级联处于冻结观察期**：不新增平台分支，不删除 `Platform` 类；按 `C3平台级联方法级清单.local.md` 执行。

## 4. 命名与类型

- 类名 PascalCase，方法/字段 camelCase，常量 UPPER_SNAKE_CASE，包名小写。
- Service 接口 `I...Service`，实现 `...ServiceImpl`；DAO `...Mapper`，动态 SQL 放 `dao/provider/...Provider`。
- 请求对象用 `*Param`/`*Request`，响应对象用 `*Result`/`*Content`；分页统一 `PageInfo<T>`。
- 严格区分：
  - `deviceId`、`channelId`：国标编码，通常 `String`；
  - `id`、`channelDbId`、`dataDeviceId`：数据库主键/外键，通常 `Integer`。
- 固定取值使用 `ErrorCode`、`InviteErrorCode`、`InviteSessionType`、`ChannelDataType` 等常量/枚举，不散落魔法值。
- 简单 POJO 用 Lombok `@Data` 或 `@Getter/@Setter`；可能为空的布尔/数值用包装类型。

## 5. Controller 规范

- 方法必须 `public`；`@RestController` 下不重复写 `@ResponseBody`。
- 新接口必须有 `@Operation`、`@Parameter`、`@SecurityRequirement(name = JwtUtils.HEADER)`；兼容接口用 `@Hidden`。
- 参数校验优先在入口完成：简单非空用 `Assert`，需要错误码时抛 `ControllerException`。
- 返回约定：
  - 普通接口直接返回 DTO、`PageInfo`、`void`，由 `GlobalResponseAdvice` 包装为 `WVPResult`；
  - `/api/v1`、`/api/video-`、`/index/hook` 等路径不自动包装，兼容接口保持原始 JSON；
  - 需要自定义 `code/msg` 时直接返回 `WVPResult<T>`。
- 分页参数统一 `page`、`count`；`PageHelper.startPage(page, count)` 后必须紧接查询，中间不插入其他 SQL。
- 异步接口使用 `DeferredResult<WVPResult<T>>`；`onTimeout` 只设置结果并通知 Service，不直接删 Redis/播放状态。

## 6. Service 与事务

- 实现类使用 `@Service`、`@Slf4j`；对外暴露接口，不直接注入实现类。
- `@Transactional` 只放在 **ServiceImpl 的 public 方法**；不放在 Controller 或接口上。
- 事务只包数据库写操作；不把 SIP 等待、ZLM HTTP、Redis 轮询放进事务。
- 同类内部调用 `@Transactional`/`@Async` 方法会绕过代理；需要时拆到另一个 Bean 或自注入。
- 业务失败抛 `ControllerException`；异步/协议回调使用 `ErrorCallback<T>`，通过 `InviteErrorCode` 表达结果。
- 查询单条允许返回 `null`，查询列表返回空集合；调用方必须判空。
- 设备/平台 BYE、事务清理优先复用 `DialogTerminationService`，不新增直接 `cmder.streamByeCmd` 的旁路。

## 7. DAO 与 SQL

- Mapper 使用 `@Mapper` + `@Repository`；多参数用 `@Param`；回填主键用 `@Options(useGeneratedKeys = true, ...)`。
- 动态 SQL 统一放 `dao/provider`，不新增 XML Mapper。
- **外部参数必须 `#{}` 绑定**；`${}` 只允许白名单排序字段或内部常量，禁止拼接用户输入。
- 集合 `IN` 查询用 `<foreach>` + `#{list[i]}`；空集合跳过条件，避免 `IN ()`。
- 仅支持 MySQL 8.4；不新增 `databaseId` 方言分支或非 MySQL Provider。
- 表名 `wvp_` 前缀，字段 snake_case；`device_id` 是国标编码，`data_device_id` 是数据库外键。
- 写操作返回影响行数；不用异常控制正常分支。
- 数据库脚本按 `数据库/<version>/` 维护；结构变更同步初始化/更新脚本。

## 8. Bean、DTO 与序列化

- 对外 DTO/Bean 字段加 `@Schema(description = "...")`；枚举/状态字段说明取值。
- 不把含 `password`、`gbPassword`、`pushKey`、`token`、`secret` 的实体直接返回；使用 DTO/VO，或加 `@JsonProperty(access = WRITE_ONLY)` / `@JsonIgnore`。
- HTTP 用 Spring Jackson，Redis 用 fastjson2；敏感字段两套序列化注解都要检查。
- 简单转换优先显式赋值；`BeanUtils.copyProperties` 只用于字段完全一致的场景。
- `WVPResult` 只表达 HTTP 业务结果；`InviteErrorCode` 只用于点播/回放等异步回调。

## 9. 异常与返回

- HTTP 业务错误统一 HTTP 200 + `WVPResult.code != 0`；认证失败、系统异常才用 4xx/5xx。
- 全局异常处理在 `conf/GlobalExceptionHandler`：
  - `ControllerException` 保留业务 code/msg；
  - `IllegalArgumentException` 映射为 `ERROR100`；
  - 其他异常返回 `ERROR500`。
- 不把 SQL、文件路径、密钥、底层堆栈拼进返回给前端的 message；详细原因写日志。
- 异步回调必须“恰好一次”：成功、失败、超时都释放认领并通知等待者；单个回调异常不影响其他回调。
- 点播等待使用 `onceAndFirst` 认领；更新路径不得清空仍在等待的回调。
- `DeferredResult` 只能成功一次；清理逻辑必须按本次请求拥有的状态做条件删除。

## 10. 日志与隐私

- 使用 Lombok `@Slf4j`；禁止新增 `System.out.println`、`printStackTrace`。
- 日志使用参数化占位符 `{}`，不字符串拼接；异常对象放最后一个参数。
- 统一中文 + 模块前缀，例如：
  - `log.info("[点播] deviceId={}, channelId={}", deviceId, channelId);`
  - `log.error("[录像下载] 处理失败: stream={}", stream, e);`
- 级别：生命周期/关键动作 `info`，参数细节 `debug`，可恢复异常 `warn`，失败/异常 `error`。
- 禁止记录密码、Token、Authorization、Redis 密码、设备口令、pushKey、完整敏感实体。
- `logback-spring.xml` 保留 `maxHistory=180`、`totalSizeCap`，满足日志不少于 180 天。

## 11. 配置与常量

- 成组配置用 `@ConfigurationProperties(prefix = "...")`，字段给默认值；单点配置才用 `@Value`。
- 配置项 kebab-case，Java 字段 camelCase；配置类通常加 `@Component`、`@Order(0)`。
- Redis key/前缀统一放 `common/VideoManagerConstants`；按实例隔离的 key 加 `userSetting.getServerId()`。
- 临时状态必须设置 TTL；超时时间优先取 `UserSetting`，不硬编码。
- 多键一致性用 `SessionCallback` + `MULTI/EXEC`；检查后删除用 `WATCH/MULTI` 或 Lua。
- 本地 profile/密码不提交；`application-*.yml` 多数被 gitignore。

## 12. 并发、异步与状态

- 共享可变状态用 `ConcurrentHashMap`、`CopyOnWriteArrayList`、`Atomic*`；不用普通 `HashMap` 跨线程读写。
- 清理 Map 用 `remove(key, expectedValue)`，避免误删其他线程刚注册的任务/回调。
- 不用 `synchronized (str.intern())` 锁设备/通道；按 key 锁优先参考 `CatalogDataManager`、`SSRCFactory` 的 `computeIfAbsent` 模式。
- 避免整个 Service 方法 `synchronized`；只锁必要临界区。
- Redis 中的 SIP 事务以 `Call-ID` 为权威，`STREAM` 只是索引；删除索引前确认仍指向当前事务。
- 延迟任务统一用 `DynamicTask`：key 全局唯一，完成/取消/超时后必须移除 future。
- 复杂并发方法用 Javadoc 写清不变量、原子边界、并发窗口、失败兜底。

## 13. 时间、空值与集合

- 时间统一走 `utils/DateUtil`，时区固定 `Asia/Shanghai`；不新增 `SimpleDateFormat`。
- 内部计算优先 `LocalDateTime`/`Instant`；对外协议时间用 `DateUtil` 转换。
- 项目不使用 `Optional`；判空使用 Spring `ObjectUtils`/`StringUtils`，注意不要与 Apache Commons 同名类混用。
- 列表/Map 返回空集合，不返回 `null`。
- 字符串判空优先 `ObjectUtils.isEmpty`；需要业务错误时抛 `ControllerException`，不静默返回。

## 14. 测试

- 使用 JUnit 5 + Mockito；纯单元测试，不启动 Spring 上下文，不依赖 MySQL/Redis/ZLM。
- 测试类放被测类同包，命名 `*Test`；方法名用英文 `method_condition_expected`。
- Mockito 统一 `@ExtendWith(MockitoExtension.class)`、`@Mock`、`@InjectMocks`。
- Provider/SQL 测试断言使用 `#{}`、不包含原始参数值；并发/清理测试断言旧任务被移除且新任务可注册。
- 修 bug 必须补回归测试，覆盖失败、超时、重复调用、并发清理中的至少一个边界。
- `pom.xml` 硬编码 `<skipTests>true</skipTests>`；跑测试用 IDE，或临时改为 `false` 后恢复。
- 改动 DAO/Service/测试后至少执行 `mvn -q -DskipTests test-compile`。

## 15. 前端（待建）

- 当前没有 `web/` 工程；不要执行 `cd web`、`npm install` 或旧前端构建命令。
- 新前端目标：Vue 3 + Vite 6 + Element Plus 2.13，构建输出 `src/main/resources/static`。
- 不引入旧依赖：`vue-ztree-2.0`、`vue-clipboards`、`mockjs`、`xlsx`、`ol`、`gcoord`。
- 通道类型只保留 1（国标）；不新增 2/3/200 的前端映射。
- 接口按后端 `WVPResult` 读取：`code`、`data`、`msg`；不重复包装。
- 不在前端保存密码/密钥，不在 console 输出 Token。

## 16. 提交与评审

- 提交信息使用中文，简短明确（建议不超过 20 字）；一个清理批次或功能点一个提交。
- 提交前至少执行 `mvn -q -DskipTests compile`、`mvn -q -DskipTests test-compile`、`git diff --check`。
- 删除类后必须 `mvn -q clean package -DskipTests`，避免 `target` 旧 class 残留。
- PR 描述包含背景、改动点、影响范围、验证方式、风险/回滚。
- 评审先给结论：建议合并 / 可合并但需处理 / 建议发回作者修改。
- 不提交 `target/`、`logs/`、`config/`、`打包/`、Docker 数据卷、本地 profile、真实口令/密钥。
- 未经明确要求，不推送远程、不重写历史。

## 17. 文档

- 文档使用简体中文，结论先行，编号章节，表格配引导句。
- 路径、命令、参数用反引号；状态/版本行用引用块；长文提供章节导览。
- 不在文档、日志、提交信息中写密码、Token、密钥、设备口令。
- 代码与文档同批更新；README、`AGENTS.md`、本规范与清理计划保持同一口径。
